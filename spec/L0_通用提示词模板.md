# L0 通用提示词模板（给完全没看过本项目的模型）

> 目标：把下面这一段直接粘给任何模型——哪怕它不知道 P/F/Q/N、没读过主标准、也没有项目上下文——它也能读懂并执行。
>
> 用法：复制 §1（英文标准版）或 §2（中文版），把 `{{P1}}` 这类占位符换成约束卡内容；不适用的行直接删掉，编号保持不变。

---

## 0. 30 秒用法

1. 选英文版或中文版，整段复制。
2. 替换 `{{...}}` 和 `{{NOTE_LIMIT}}`；注释上限按积分/难度取 150/300/600/900/1,200/1,500（D0–D5）；D6+ 先拆卡。D0 少于 D1，D1 只留 1 条 P、2 条 F、3 条 Q。
3. 把整段作为一个 user message 发给模型；**不要**再加"要有创意""画好看点"之类的话。
4. 模型返回后，从 `<svg` 开始截到 `</svg>`，存成 `creature.svg`；`---` 后面的内容存成 `design.md`。
5. 按 §5 的清单人工过一遍。

> 这段 prompt 故意写得很"硬"：它不靠模型自由发挥，靠的是"每条约束都要在图上找到、找不到就说遮挡"。越少额外提示，结果越可比。

## 1. English template（标准版，复制这一段）

> 注释上限：D1 = 300 词，D2 = 600 词，D3 = 900 词；把三处 `{{NOTE_LIMIT}}` 都换成对应数字。

```text
You are an alien-creature designer. Your job is to turn a set of written constraints into ONE clear SVG drawing, plus a short design note that maps each constraint to something visible in the drawing.

Do not ask questions. Make reasonable choices and explain them in the note.

=== WHAT TO PRODUCE ===

1) One SVG drawing of a single original alien creature.
2) A design note of at most {{NOTE_LIMIT}} words.
3) A line containing only three hyphens between them: ---

=== SVG RULES ===

- Return raw SVG code. Start with <svg ...> and end with </svg>.
- Do not wrap the SVG in markdown code fences.
- Do not write anything before the SVG.
- The root <svg> must have xmlns="http://www.w3.org/2000/svg" and viewBox="0 0 512 512".
- Show the whole body, in side view or three-quarter view. Do not crop the creature.
- One creature only. No collage, no multiple poses, no extra creatures.
- Do not use any <text> element. Do not write the creature's name or label its parts. Draw the features instead.
- Do not use <image>, <foreignObject>, <script>, external URLs, or embedded raster images.
- The SVG must render in a browser with no external files.
- A simple background is allowed, but it must not hide the body.
- Color is allowed. Shape and structure matter more than color.
- If a size constraint cannot be judged from the drawing, you may add a simple scale bar with no text; explain it in the note.
- Keep the file under 512 KB.

=== HOW TO READ THE CONSTRAINTS ===

Each constraint has an ID and a group:

P = global parameter (body size, biochemistry, environment). These are the canvas. Do not violate them.
F = free design goal (where it lives, how it feeds, what organ it has). You choose the shape that shows it.
Q = exact count or prohibition (number of limbs, eyes, openings). Count carefully. "Exactly 3" means 3, not 2 or 4.
N = body-plan rule (spine, feet, exoskeleton). These are anatomy rules.

If two constraints cannot both be true, follow this priority:
P > F > Q > N.
Keep the higher group, sacrifice the lower one, and explain the conflict in the note.
If a constraint is impossible even after following the priority, do not ignore it silently: choose the closest possible design and explain the compromise.

Bonus (optional, independent of the groups):
- Avoid humanoid features (no human face, human hands, human torso, upright human proportions).
- Avoid soft-bodied/blob features (no slime, jelly, or a body that is only tentacles; give it a skeleton, shell, or plates).
These are optional. They do not override the constraints.

=== THE CONSTRAINTS ===

P1: {{P1}}
P2: {{P2}}
F1: {{F1}}
F2: {{F2}}
F3: {{F3}}
F4: {{F4}}
Q1: {{Q1}}
Q2: {{Q2}}
Q3: {{Q3}}
Q4: {{Q4}}
Q5: {{Q5}}
Q6: {{Q6}}
N1: {{N1}}
N2: {{N2}}

Remove lines that do not apply. Keep the IDs stable.

=== THE DESIGN NOTE ===

After the SVG and the --- line, write the note.

- At most {{NOTE_LIMIT}} words.
- One line per constraint, in this exact form:
  P1 → the visible feature that shows it
  Q1 → the visible feature that shows it
- The note must point to something in the drawing. Do not write lore, history, or long explanations.
- The drawing is the primary answer. A feature that is only described in the note but not drawn does not count.
- If a constraint is hidden in this view, say so and say where it is:
  Q1 → the third feeding opening is on the far side; hidden in this view.
- If a constraint is satisfied by the overall body plan, say that:
  N1 → no vertebrae; the body is supported by a mineral shell.
- If two constraints conflict, add a line:
  CONFLICT: F2 (rigid dorsal crest) vs N1 (no vertebrae) → followed F2; the crest is a mineral plate, not a vertebral column.
- Do not claim a feature is visible if it is not.
- If you had to omit something, say what you omitted and why.
- Do not add constraints that were not asked for.
- Stop after the note. Do not add a summary, score, or extra commentary.

=== OUTPUT SHAPE ===

<svg ...>
...
</svg>
---
P1 → ...
P2 → ...

=== SELF-CHECK BEFORE YOU ANSWER ===

1. Is there exactly one creature, full body, in side or three-quarter view?
2. Does the SVG have viewBox="0 0 512 512" and no external references?
3. Are all Q counts exact, and are all prohibitions respected?
4. Is there any <text> element? If yes, remove it.
5. Does every constraint have one line in the note?
6. Is every claimed feature actually visible (or marked hidden)?
7. Is the note at most {{NOTE_LIMIT}} words?
8. If there was a conflict, is it explained with a CONFLICT line?

If any answer is no, fix it before answering.
```

## 2. 中文版（同样结构，给中文模型或你自己读）

> 注释上限：D1 = 300 词，D2 = 600 词，D3 = 900 词；把三处 `{{NOTE_LIMIT}}` 都换成对应数字。

```text
你是一名外星生物设计师。你的任务是把一组文字约束变成一张清晰的 SVG 图，并附一份简短的设计说明，把每条约束对应到图上可见的特征。

不要提问。自己做合理判断，并在说明里写清楚。

=== 你要产出什么 ===

1) 一张 SVG 图，画一个原创的外星生物。
2) 一份不超过 {{NOTE_LIMIT}} 词的设计说明。
3) 两者之间用一行只包含三个连字符的分隔线：---

=== SVG 规则 ===

- 直接输出 SVG 代码，从 <svg ...> 开始，到 </svg> 结束。
- 不要把 SVG 放进 markdown 代码块。
- SVG 前面不要写任何文字。
- 根元素 <svg> 必须有 xmlns="http://www.w3.org/2000/svg" 和 viewBox="0 0 512 512"。
- 画全身，侧视或 3/4 视，不要裁切。
- 只画一个生物。不要拼贴、不要多个姿态、不要额外的生物。
- 不要使用任何 <text> 元素。不要写生物的名字，不要给部位贴标签。用画出来的特征表达。
- 不要使用 <image>、<foreignObject>、<script>、外部 URL 或嵌入的位图。
- SVG 必须能在浏览器里直接显示，不依赖外部文件。
- 允许简单背景，但不能遮住身体。
- 允许颜色。形状和结构比颜色更重要。
- 如果体型约束无法从图中判断，可以在角落画一个无文字的比例尺，并在说明里解释。
- 文件小于 512 KB。

=== 怎么读约束 ===

每条约束有一个编号和一个组：

P = 全局参数（体型、生化、环境）。这是画布，不能违反。
F = 自由需求（住在哪、怎么进食、有什么器官）。你选择能表现它的形状。
Q = 精确数量或禁止项（肢体、眼睛、开口的数量）。仔细数。"恰好 3 个"就是 3 个，不是 2 个或 4 个。
N = 身体结构规则（脊椎、足、外骨骼）。这是解剖规则。

如果两条约束不能同时成立，按这个优先级：
P > F > Q > N。
保留高的，牺牲低的，并在说明里解释冲突。
如果按优先级仍然无法满足，不要默默忽略：选择最接近的设计，并说明妥协。

加分项（可选，独立于四个组）：
- 尽量避免人形特征（人脸、人手、人形躯干、双足直立比例）。
- 尽量避免软体/黏液/果冻/纯触手团；给它骨架、甲壳或板甲。
这些是可选的，不覆盖约束。

=== 约束 ===

P1: {{P1}}
P2: {{P2}}
F1: {{F1}}
F2: {{F2}}
F3: {{F3}}
F4: {{F4}}
Q1: {{Q1}}
Q2: {{Q2}}
Q3: {{Q3}}
Q4: {{Q4}}
Q5: {{Q5}}
Q6: {{Q6}}
N1: {{N1}}
N2: {{N2}}

删掉不适用的行，保持编号不变。

=== 设计说明 ===

在 SVG 和 --- 之后写说明。

- 不超过 {{NOTE_LIMIT}} 词。
- 每条约束一行，格式固定：
  P1 → 图上可见的特征
  Q1 → 图上可见的特征
- 说明必须指向图里的东西。不要写世界观、历史或长篇解释。
- 图是主答案。只在说明里写、图上没画的特征，不算。
- 如果某个特征在这个视角被遮住，明说，并说它在哪里：
  Q1 → 第三个进食口在背面；这个视角看不到。
- 如果某条约束是由整体身体结构满足的，直接说：
  N1 → 无脊椎；身体由矿物甲壳支撑。
- 如果两条约束冲突，加一行：
  CONFLICT: F2（硬的背冠）vs N1（无脊椎）→ 按 F2；背冠是矿化板，不是脊椎。
- 图上没有的特征，不要说它可见。
- 如果省略了什么，说清楚省略了什么、为什么。
- 不要增加没要求的约束。
- 说明写完就停。不要加总结、评分或额外评论。

=== 输出形状 ===

<svg ...>
...
</svg>
---
P1 → ...
P2 → ...

=== 回答前自检 ===

1. 是不是只有一个生物、全身、侧视或 3/4 视？
2. SVG 是否有 viewBox="0 0 512 512"，且没有外部引用？
3. 所有 Q 的数量是否精确？所有禁止项是否遵守？
4. 有没有 <text>？有就删掉。
5. 每条约束在说明里是否都有一行？
6. 说明里声称可见的特征，图上是否真的可见（或已标为遮挡）？
7. 说明是否不超过 {{NOTE_LIMIT}} 词？
8. 如果有冲突，是否写了 CONFLICT 行？

任何一项为"否"，先改再回答。
```

```text
P1 → the creature is about 1.5 m long; the scale bar at lower left is 0.5 m.

F2 → a dorsal sac glows orange and has three heat vents.
```

## 4. 模型应该输出成什么样

```text
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 512 512">
  ... 一个生物，全身，侧视/3/4 视 ...
</svg>
---
P1 → ...
F1 → ...
Q1 → ...
```

- `<svg>` 前没有任何文字；
- `</svg>` 和 `---` 之间没有解释；
- `---` 后是逐条说明；
- 说明后没有总结、评分或"希望你喜欢"。

## 5. 常见失败与处理

| 现象 | 处理 |
|---|---|
| 用 ```svg 包住 | 去掉首尾 fences，保存里面的内容 |
| 前面有"好的，我来画……" | 从 `<svg` 开始截取，前面丢弃 |
| 用 `<text>` 写生物名字/部位 | 记 `text_label`；要求重跑，或在该项记红 |
| 画了多个生物/拼贴 | 记"一个生物"红 |
| Q 的数量不对 | 记对应 Q 红；不要帮它改图 |
| 说明写了、图上没有 | 记说明准确性红（图文不符） |
| 说明超过上限（D0 150 / D1 300 / D2 600 / D3 900 / D4 1,200 / D5 1,500） | 记克制红 |
| 问澄清问题 | 不回答；按"不要提问"重跑 |
| 输出 HTML/React 而不是 SVG | 记渲染红 |
| 画成人形/软体团 | 不给加分徽章；约束本身仍可能及格 |

## 6. 人工自检 8 项

- [ ] SVG 能在浏览器里打开，不是空白
- [ ] 只有一个生物，全身，没被裁切
- [ ] 所有 Q 的数量精确，禁止项都遵守
- [ ] 没有 `<text>` 元素
- [ ] 每条约束在说明里都有一行
- [ ] 说明没有"图文不符"；遮挡声明是真的
- [ ] 说明 ≤ 上限（D0 150 / D1 300 / D2 600 / D3 900 / D4 1,200 / D5 1,500）
- [ ] 有冲突的话，CONFLICT 行写清楚了

## 7. 使用注意

- **不要加戏**：不要加"要有创意""画得漂亮""可以夸张一点"。这会改变题目，破坏可比性。
- **系统提示词留空**：如果聊天 UI 自带 system prompt，尽量留空；不能留空就记录在 Manifest 里。
- **保存原始 SVG**：不要截图、不要转 PNG、不要手工修图；原始 SVG 是复现的依据。
- **记录参数**：模型名、版本/日期、温度、采样次数、是否开推理、是否用工具。
- **失败也交**：没画出 SVG、被截断、空白，都按失败记录；不要重试到成功再交。
- **一次只改一个变量**：换模型就固定 prompt；换 prompt 就固定模型。否则不知道差异从哪来。
