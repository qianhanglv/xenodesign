# 提示词撰写指南：从要求词到 L 级提示词

> 工作名：**XenoDesign Prompt Authoring Guide**
> 版本：v1.0 · 2026-11-13
> 作用：教 AI（或人）把一组原始"要求词"编译成完整、自包含、可执行的 L 级提示词，并自动设置注释上限。
> 关系：配合 [异星生物设计_主标准.md](异星生物设计_主标准.md) 与 [L0_通用提示词模板.md](L0_通用提示词模板.md) 使用。

---

## 0. 一句话

**输入**一组要求词（例如"硅基、岩浆、三个进食口、无眼、无脊椎"）+ 可选难度/层级；
**输出**一份完整提示词、一张约束卡 JSON、一张"要求词 → 约束 ID"对照表，以及符合难度上限的注释规则。

**核心规则**：注释上限随难度增长——

| 难度 | 约束量 | 注释上限 |
|---|---|---|
| **D1 低** | 4–6 条 | **300 词** |
| **D2 中** | 7–13 条 | **600 词**（2×） |
| **D3 高** | 14–20 条 | **900 词**（3×） |

上限是"最多"，不是"必须写满"；**按任务计，不按视图计**。L1 的六视图、L4 的完整动画、L5 的骑车，都共用同一个上限，写不下就压缩——压缩本身就是克制测试。

---

## 1. 输入与输出

| | 内容 |
|---|---|
| **输入** | 要求词列表（原始短语即可）；可选：难度 D1/D2/D3、层级 L0–L5、优先级覆盖 |
| **输出 A** | 对照表：要求词 → 约束 ID → P/F/Q/N → 怎么查 |
| **输出 B** | 约束卡 JSON：id、difficulty、load、priority、constraints、bonus、conflicts、annotation_limit |
| **输出 C** | 完整提示词（可直接粘给被测模型） |
| **输出 D** | 校验清单：15 项，逐项过 |

**不要**输出解释、创作建议、额外约束。只输出 A–D。

---

## 2. 七步流程

| 步 | 动作 | 产出 |
|---|---|---|
| 1 | **收集**：逐条抄下要求词，不改写 | 原始列表 |
| 2 | **分类**：每条标 P/F/Q/N | 带类别的列表 |
| 3 | **规范化**：把模糊词改成可见/可数/可查的表述 | 约束条目 |
| 4 | **计数定难度**：按条数落档，设注释上限 | difficulty + annotation_limit |
| 5 | **冲突检查**：跨类按优先级；同类冲突退回作者 | 冲突列表/修正建议 |
| 6 | **组装**：套 L 级提示词骨架，写入上限 | 完整提示词 |
| 7 | **校验**：15 项检查，全部通过才交 | 校验清单 |

## 3. 分类：P / F / Q / N

### 3.1 四个问题

对每条要求词，按顺序问：

1. **它是不是一个全局参数**，不规定具体器官/数量？→ **P**
2. **它是不是一个开放目标**，能用多种形状满足？→ **F**
3. **它是不是在定义身体规划/结构类别**（脊椎、足、外骨骼、肺、对称、分节）？→ **N**
4. **剩下的，是不是对可重复部件的精确数量或禁止项**（眼、肢、开口、翅膀），或硬性几何比例（如贯穿空腔 ≥1/3）？→ **Q**

> 分类顺序是 **P → F → N → Q**，不是冲突优先级 **P > F > Q > N**。先问 N，是为了避免把"无脊椎"这种结构规则误判成"0 条脊椎"的数量规则；如果先问 Q，它一定会被"无"字带走。

### 3.2 判定标准

| 类 | 定义 | 通过测试 | 反例 |
|---|---|---|---|
| **P** | 全局参数，不影响器官布局 | 能用一句参数描述；不指向某个部位 | "有三条腿"不是 P |
| **F** | 开放式设计目标 | 可以用多种形态满足；需要说明书指认 | "恰好三个口"不是 F |
| **Q** | 精确数量或禁止项（针对可重复部件），或硬性几何比例 | 可数、可检查"有没有多" | "无脊椎"不是 Q（是 N） |
| **N** | 身体规划/结构类别 | 在剖面/骨骼里可见；影响整体结构 | "三个口"不是 N（是 Q） |

### 3.3 例子表

| 要求词 | 类 | 理由 |
|---|---|---|
| silicon-based biochemistry | P | 全局生化参数 |
| body length 2–3 m | P | 全局体型参数 |
| lives in molten rock | F | 栖息地，开放目标 |
| stores heat in a dorsal organ | F | 功能/器官，形态可多种 |
| communicates by vibration | F | 功能，形态可多种 |
| exactly three feeding openings | Q | 精确数量 |
| no eyes | Q | 可数部位的禁止项 |
| no more than four limbs | Q | 数量上限 |
| no wings | Q | 可数附件的禁止项 |
| no vertebrae | N | 身体结构/分类 |
| no feet; moves on a muscular foot | N | 运动结构/身体规划 |
| exoskeleton of mineral plates | N | 外骨骼结构 |
| radial symmetry | N | 身体对称规划 |

**边界案例**：

- "six limbs" → **Q**（数量），不是 N；但"六肢身体规划"可以在说明书里补充。
- "no feet" → **N**（身体规划），不是 Q；它不是一个"脚的数量"，而是"有没有脚"这个结构类别。
- "no wings" → **Q**（附件禁止项）；翅膀是可数附件，不是身体规划。
- "no eyes" → **Q**；眼睛是可数部位。
- "must be scary" → **拒绝**；不可见、不可数、不可查。请作者改成可见特征（如"外露的锯齿状牙齿、无眼"），或删掉。
- "weird skin" → **拒绝/改写**；改成"半透明晶体板 + 矿物接缝"这类可见描述。

### 3.4 一条要求 = 一个 ID

- 复合句要拆："lives in magma and eats rocks" → `F1` + `F2`；
- 重复的合并；同义的去重；
- 不要替作者新增要求；
- 不要丢掉任何一条。

## 4. 规范化：把"词"变成"可查的约束"

### 4.1 五条规则

1. **可见**：外行能在图上指出来；指不出来就改写。
2. **可数**：数量写成"恰好/最多/至少 N"，不要写"几个/若干"。
3. **可查**：说明里能写出"在图上哪个位置"；写不出就说明太虚。
4. **单义**：一个词只表达一件事；"大型硅基捕食者"拆成体型、生化、食性三条。
5. **不改意图**：可以换词，不可以换设定；拿不准就标注 `interpreted: ...`，让作者确认。

### 4.2 改写前后

| 原始要求词 | 改写后 | 类 |
|---|---|---|
| big | body length 2–3 m | P |
| silicon | silicon-based biochemistry; crystal/mineral body | P |
| lives in lava | lives in molten rock | F |
| several mouths | exactly three feeding openings | Q |
| no eyes | no eyes; no eye-like structures | Q |
| no backbone | no vertebrae | N |
| scary | 拒绝；请改成可见特征（如"外露锯齿、无眼"） | — |
| weird skin | translucent crystal plates with mineral seams | F |

> 改写的底线：**只改表达，不改设定**。把"大"改成"2–3 米"可以；把"岩浆"改成"深海"不行。

## 5. 难度与注释上限

### 5.1 落档

| 难度 | 约束条数 | 典型构成 | 注释上限 | 冲突预算 |
|---|---|---|---|---|
| **D1** | 4–6 | 1P + 2F + 3Q | **300 词** | 0 |
| **D2** | 7–13 | 2P + 4F + 6Q + 1N | **600 词** | 0–1 |
| **D3** | 14–20 | 3P + 6F + 9Q + 2N | **900 词** | 1–2 |

- 条数落在哪档，就用哪档的上限；**不按逐条算**。
- 600 = 2 × 300；900 = 3 × 300。这就是"中难度是低难度两倍"的落法。
- D1 通常无 N；如果 4–6 条里已经含 N，按 D2 处理（因为要查剖面/骨骼），上限 600。
- 超过 20 条：拆成两张卡，不要硬塞。
- **上限是每个任务的总量**，不是每张视图的量。L1 的六视图、L4 的完整动画，共用同一个上限。
- 主标准里的 6/13/20 是**标称构成**；实际卡片落在 7–13 就按 D2，不要求正好 13 条。

### 5.2 中文怎么算

英文按单词数；中文按 **1.5 倍字数**折算：

- D1：300 词 ≈ 450 字
- D2：600 词 ≈ 900 字
- D3：900 词 ≈ 1350 字

提示词里要写清楚按哪种计；不要既说"300 词"又按字符数卡。

### 5.3 注释必须包含什么

无论 L0 还是 L5，注释都必须：

1. 每条约束一行，格式 `P1 → 图上可见的特征`；
2. 看不到的特征写 `hidden in this view`，并说位置；
3. 冲突写 `CONFLICT:` 行，说明保留哪条、牺牲哪条；
4. L1+ 写 `Source: L0 <id>`，声明复用源设计、没有重画；
5. 不写世界观、历史、长解释；
6. 不超过上限。

**L 级别只改变"要覆盖的视图"，不改变"注释上限按难度走"这条规则。**

## 6. 冲突处理

### 6.1 跨类冲突

按 `P > F > Q > N`：默认保留高的、牺牲低的，在提示词里加 `CONFLICT` 指令，并在注释里写清楚。如果两者其实能共存、只是需要解释，按 §6.3 保留两条并写 `RECONCILE`。

### 6.2 同级别冲突：先分三种

"同级别"指同一个组（P/P、F/F、Q/Q、N/N）。不要一律当死题，也不要一律硬解；先分三类：

| 类型 | 判定 | 例子 | 处理 |
|---|---|---|---|
| **直接矛盾** | 同一个维度取了两个不同值 | P-02 碳基 + P-02 硅基；Q-13 无眼 + Q-13 恰好 2 眼；N-01 有脊椎 + N-01 无脊椎 | 二选一；除非卡片明确是"矛盾挑战"，否则不发货 |
| **不可兼得** | 不同维度，但两个目标互斥 | F-01 岩浆 + F-03 冰下；F-09 光合 + F-02 深海 | 二选一，或改写成边界环境；改写后算 Tension |
| **需要解释** | 不同维度，可以共存，但必须说明 | Q-01 4 肢 + Q-02 2 腿；N-01 无脊椎 + N-03 内骨骼；F-20 拟态 + F-25 变色 | 保留两条，写 `RECONCILE:`；算 Tension |

> 处理同级别冲突的目标不是"消灭冲突"，而是"让冲突可解释、可核对"：能二选一就二选一，能共存就写 `RECONCILE`，不能共存就不要发货。

**判定顺序**：

1. 同维度？→ 直接矛盾。
2. 不同维度但互斥？→ 不可兼得。
3. 不同维度但可共存？→ Tension。
4. 不同类？→ 先按 `P > F > Q > N`；低的被牺牲后仍自洽，就牺牲；如果会产生 Tension，就保留并写 `RECONCILE`。

**直接矛盾的唯一例外**：卡片故意考"冲突处理"。这时必须给 `tie_break`：

- `lower_id_wins`：编号小的赢；
- `higher_id_wins`：编号大的赢；
- `more_specific_wins`：更具体的赢；
- `author_choice`：作者指定。

并在提示词里写清楚；不能让被测模型自己猜。

### 6.3 Tension：保留两条，写 RECONCILE

Tension 不是"谁让路"，而是"两条都要，解释怎么共存"。例：

```text
RECONCILE: Q1 (4 limbs) = Q2 (2 legs) + Q3 (2 manipulators). The total is the sum of the parts; no extra limbs.
```

规则：

1. 两条都保留；
2. 在注释里写 `RECONCILE:` 行，说明怎么共存；
3. 提示词里写 `RECONCILE` 格式；
4. 解释不了，就降级为"不可兼得"，二选一。

**不要把 Tension 当死题**：它是 D2/D3 的难点，不是错误。

### 6.4 有意的冲突 / 提示词里怎么写

如果卡片就是要考"冲突处理"，必须满足：

1. 冲突可解释，不是死题；
2. 说明里给出合理的重新解释；
3. 提示词写明 `tie_break`（同类）或 `P > F > Q > N`（跨类）；
4. 注释用 `CONFLICT:` 或 `RECONCILE:`。

提示词模板（无论有没有冲突都建议保留）：

```text
If two constraints seem to conflict:
1. If they can coexist with an explanation, keep both and write a RECONCILE line.
2. If they cannot coexist and are in different groups, follow P > F > Q > N; write a CONFLICT line.
3. If they cannot coexist and are in the same group, follow the stated TIE-BREAK; if none is stated, keep the more specific constraint; write a CONFLICT line.
```

有同类直接矛盾时，在提示词里加一行 `TIE-BREAK: lower_id_wins`（或你选的规则）；没有就不加。

约束卡里的记录方式：

```json
{
  "conflicts": [
    { "pair": ["Q1", "Q2"], "type": "direct", "resolution": "kept Q1; Q2 dropped" }
  ],
  "tension": [],
  "tie_break": "more_specific_wins"
}
```

如果有 Tension，把 `tension` 填成 `["T-01"]`，并在 `conflicts` 里加一条 `type: "tension"` 的记录。

## 7. L 级别怎么加（完整提示词块）

L0 用模板；L1–L5 是在 L0 之后**追加**的指令。所有层级：

- 复用同一份 source package；
- 注释上限按难度，不按层级；
- 不重写 L0 的角色、SVG 规则、约束清单、输出格式；
- 完成不了某一层，就交"该层失败"，不要重画一只新生物。

### 7.1 通用 source reuse

```text
Using the same creature as the source, draw ...
Do not redesign the creature.
```

**源包**：`source/creature.svg` + `source/design.md` + 可选 `preview.png`；Manifest 记 `source_mode` 和 `source_hash`。

### 7.2 L1：六视图

```text
Using the same creature as the source, draw six orthographic views:
front, back, left, right, top, bottom.

One SVG per view, named front.svg, back.svg, left.svg, right.svg, top.svg, bottom.svg.
Use the same scale and alignment in every view. No perspective.
Keep every count, pattern, and proportion identical across views.
If a feature is hidden in one view, it still exists in the design; do not delete it.
Do not redesign the creature.
```

| 代号 | 检查 | 失败长什么样 |
|---|---|---|
| V1 | 六个文件齐全 | 少一个方向 |
| V2 | 数量一致 | 正面 3 肢、背面 4 肢 |
| V3 | 比例/对齐一致 | 头突然变大、身体错位 |
| V4 | 花纹/特征一致 | 正面有斑、背面没有 |
| V5 | 与 L0 源一致 | 画成另一只生物 |
| V6 | 遮挡不删除 | 背面看不到的口直接消失 |

### 7.3 L2：剖面

```text
Using the same creature as the source, draw a cutaway or cross-section SVG
(section.svg, same viewBox).

Choose a plane that shows how all feeding openings connect to a shared digestive cavity.
Show the cavity inside the body outline. Show the structural material
(crystal, mineral, bone, or shell).
Do not label the image. Add one line to the note for each internal feature.
Do not redesign the exterior.
```

| 代号 | 检查 | 失败长什么样 |
|---|---|---|
| S1 | 所有开口都连到腔体 | 只画一条通道 |
| S2 | 腔体在外轮廓内 | 器官跑到身体外面 |
| S3 | 材质与 P 一致 | 硅基生物画出血肉 |
| S4 | 无环境矛盾 | 岩浆生物画出鳃/水肺 |
| S5 | 外轮廓与 L0 一致 | 剖面是另一只生物 |

### 7.4 L3：骨骼 + 拓扑皮张

L3 有两个产出，分开画、分开查。**皮张不是剖面，也不是爆炸图**；它是一张连续皮展开后的平面图。

**骨骼**：

```text
Using the same creature as the source, draw skeleton.svg:
the structural frame, with a faint outline of the body.
Keep the same viewBox.

Joints and limbs must align with the exterior.
Keep the same number of limbs, openings, and segments; do not add or remove any.
```

**皮张（拓扑展开）**：

```text
Also draw pelt.svg: the skin removed as ONE continuous piece and unfolded flat,
like a tiger pelt stretched on the ground. Keep the same viewBox.

Show the complete outer surface, the seam/incision lines, and how the pattern
continues across them.

Treat the skin as a single 2D surface with holes: every feeding opening, eye,
limb socket (or sleeve), and tail base must appear as a hole, a boundary, or an
extension in the sheet.

Show the dorsal / ventral / left / right layout and where the seams run.
The sheet must be one connected piece, not several pieces laid side by side.

Do NOT draw a cutaway.
Do NOT draw an exploded view.
Do NOT separate the skin into multiple pieces.
Do NOT change the creature's counts or pattern.
```

**为什么这样写**：

| 措辞 | 防的是什么 |
|---|---|
| `ONE continuous piece` | 防止画成多块皮拼贴 |
| `unfolded flat, like a tiger pelt` | 防止画成剖面/爆炸图 |
| `single 2D surface with holes` | 逼模型做拓扑展开，而不是"去掉皮" |
| `every opening / eye / limb / tail base` | 让孔洞可以逐一核对 |
| `dorsal / ventral / left / right layout` | 逼模型交代展开方向 |
| `pattern continues across seams` | 测花纹连续性，不是画个轮廓 |
| `Do NOT draw a cutaway / exploded view` | 直接拦住把皮张画成剖面/爆炸图的错误 |

| 代号 | 检查 | 失败长什么样 |
|---|---|---|
| K1 | 骨架支撑轮廓 | 骨骼和外形对不上 |
| K2 | 肢体数一致 | 外 4 肢、骨 6 肢 |
| K3 | 开口有支撑 | 口悬空，没有环/管 |
| K4 | 皮张是**一张连续皮** | 画成三四块皮 |
| K5 | 孔洞全部对上 | 少了眼/口/肢/尾根 |
| K6 | 接缝 + 花纹连续 | 花纹在接缝处断开 |
| K7 | 背/腹/左/右布局合理 | 展开方向说不清 |
| K8 | 不是剖面/爆炸图 | 画成切开的内部结构 |

### 7.5 L4：完整动画（跑跳）

```text
Using the same creature as the source, animate a full locomotion cycle:
idle -> run -> jump -> land -> idle.

Output motion.svg: one self-contained animated SVG using SMIL or CSS.
Use the same 512x512 viewBox. Duration: 2-4 seconds. Loop seamlessly.

Keep the anatomy identical in every frame: same limb count, opening count,
pattern, and proportions.
Show weight, contact, anticipation, and follow-through.
No limb teleportation, no sliding feet, no changing counts.

If you cannot animate, output 8-12 frames as frame01.svg ... frame12.svg
and say so in the note.
```

**4 帧故事板不算 L4。** L4 的最低要求是 `motion.svg`，或 8–12 帧降级并在注释里说明；4 帧只够做分镜，不够做动态核算。

| 代号 | 检查 | 失败长什么样 |
|---|---|---|
| M1 | 循环无缝 | 首尾帧跳变 |
| M2 | 数量稳定 | 跑着跑着多一条腿 |
| M3 | 运动顺序合理 | 没有预备/落地，直接平移 |
| M4 | 接触/重量 | 脚在地上滑，跳起来没有弧线 |
| M5 | 特征持续 | 花纹/开口中途消失 |
| M6 | 与源一致 | 动画里是另一只生物 |
| M7 | 降级声明 | 交帧序列但没说明 |

### 7.6 L5（可选）：致敬骑自行车

L5 是彩蛋，不是核心标准，也不是"回到载具题"。它只用于致敬鹈鹕测试；不计入 L0–L4 的必做链路。

```text
Optional capstone. Using the same creature as the source, show it riding a bicycle.
Use the same viewBox.

Draw the bicycle with two wheels, a frame, handlebars, and pedals.
Show the riding relation: the creature is on the bicycle, in contact with the
seat and pedals, not floating beside it.
The bicycle is an object, not a second creature.

Animate a pedaling/balance cycle (ride.svg) or draw one clear scene (ride.svg).
Keep the creature's anatomy and pattern identical to the source.
```

| 代号 | 检查 | 失败长什么样 |
|---|---|---|
| R1 | 自行车结构 | 只有两个圈，没有车架/踏板 |
| R2 | 骑乘关系 | 生物飘在车旁边 |
| R3 | 踩踏/平衡 | 脚不跟踏板，车不倒也不动 |
| R4 | 与源一致 | 换了另一只生物 |
| R5 | 单生物 + 无文字 | 多画一只生物/写标签 |

### 7.7 文件与注释

| 层级 | 文件 | 注释里必须写 |
|---|---|---|
| L0 | `creature.svg` + `design.md` | 每条约束 → 可见/遮挡 |
| L1 | `front/back/left/right/top/bottom.svg` | `Source: L0 <id>` + 六视图一致性 |
| L2 | `section.svg` | 开口连通、腔体、材质 |
| L3 | `skeleton.svg` + `pelt.svg` | `PELT: one continuous sheet; seams...; holes...` |
| L4 | `motion.svg` 或 `frame01–12.svg` | `MOTION: loop Xs; contact...; frames...` |
| L5 | `ride.svg` | `RIDE: bicycle...; contact...`（可选） |

**注释上限仍然按难度**：D1 300 / D2 600 / D3 900，按任务不按视图。L3/L4 的注释要覆盖新增视图，但不能超上限。

### 7.8 层级检查矩阵

| 层级 | 核心问题 | 一句话判据 |
|---|---|---|
| L1 | 六个方向是不是同一只？ | 数量/比例/花纹跨视图一致 |
| L2 | 内部撑不撑得住外部？ | 所有开口连到腔体，腔体在轮廓内 |
| L3 | 皮张是不是一张连续拓扑面？ | 一张皮、孔洞全、接缝连续、不是剖面 |
| L4 | 动起来还是不是同一只？ | 循环无缝、数量不变、接触/重量对 |
| L5 | 骑车是不是真的骑？ | 车结构完整、身体接触车、不是漂浮 |

## 8. 提示词骨架

完整提示词必须包含这 9 节（顺序固定）：

1. **角色 + 不要提问**；
2. **产出什么**：一张 SVG + 一份注释 + `---` 分隔；
3. **SVG 规则**：viewBox 512、全身、单生物、无 `<text>`、无外链、无位图、<512 KB；
4. **约束组 + 优先级**：解释 P/F/Q/N，写 `P > F > Q > N`；有同类直接矛盾时写 `TIE-BREAK`；
5. **加分项**：non-humanoid、non-soft（可选、独立）；
6. **约束清单**：P1…、F1…、Q1…、N1…，逐条；
7. **注释规则**：每条一行、可见/遮挡、`CONFLICT`/`RECONCILE`、`Source:`、**上限 `{{NOTE_LIMIT}}` 词**、不写世界观；
8. **输出形状**：SVG → `---` → 注释；
9. **自检 8 项**：单生物、viewBox、数量、无 text、每条一行、图文一致、不超上限、冲突有解释。

L1–L5 在第 6 节后插入对应视图指令，并保留第 7–9 节。

> 完整措辞直接用 [L0_通用提示词模板.md](L0_通用提示词模板.md) 的 §1；把其中的 `{{NOTE_LIMIT}}` 换成 300/600/900 即可。不要重写一套自己的规则。

## 9. 给 AI 的元提示词（复制即用）

```text
You are a prompt author for XenoDesign, a benchmark for alien-creature design.

INPUT
- Requirement words: {{REQUIREMENTS}}
- Optional difficulty: {{D1 | D2 | D3 | auto}}
- Optional L-level: {{L0 | L1 | L2 | L3 | L4 | L5}} (default L0)
- Optional priority override: {{...}}

TASK
Turn the requirement words into a complete, self-contained prompt that a model with no project context can execute.

STEP 1 — TRACE
For each requirement, create exactly one constraint with an ID.
Do not invent or drop any.
Classify each as (in this order; this is not the conflict priority):
P = global parameter (size, biochemistry, environment)
F = free design goal (habitat, function, organ)
N = body-plan rule (spine, feet, exoskeleton, symmetry)
Q = exact count or prohibition of a repeatable part (eyes, limbs, openings, wings)
If a requirement is compound, split it. If it is vague, rewrite it into a visible/countable form and mark "interpreted: ...".

STEP 2 — COUNT AND SET DIFFICULTY
Count constraints:
4-6 -> D1, annotation cap 300 words
7-13 -> D2, annotation cap 600 words
14-20 -> D3, annotation cap 900 words
>20 -> split into two cards
If a 4-6 card contains N, treat it as D2.
The annotation cap is per task, not per view.
Tension quota:
D1: 0
D2: 0-1
D3: 1-2 (at least one)

STEP 3 — CONFLICT CHECK
Cross-class conflicts: P > F > Q > N. Keep the higher, sacrifice the lower, and include a CONFLICT instruction.
Same-class conflicts: classify as direct contradiction, incompatible goals, or tension.
- direct contradiction (same dimension): drop one, or define a tie_break; never ship an unresolvable card.
- incompatible goals (different dimensions, mutually exclusive): choose one, or reconcile into a boundary case.
- tension (different dimensions, can coexist): keep both, mark it with a T-id, and include a RECONCILE instruction.
Never ship dead cards like "no limbs + exactly 3 limbs" or "carbon-based + silicon-based".
If the card intentionally includes a direct contradiction, state the tie_break (lower_id_wins / higher_id_wins / more_specific_wins / author_choice).

STEP 4 — WRITE THE PROMPT
Use exactly these sections:
1. Role and no-questions instruction.
2. What to produce: one SVG + one design note + a --- separator.
3. SVG rules: viewBox 0 0 512 512, full body, side/3-4 view, one creature, no <text>, no external refs, no raster, <512 KB.
4. Constraint groups and priority.
5. Bonus (non-humanoid, non-soft).
6. Constraints: P1..., F1..., Q1..., N1... with exact wording.
7. Design note rules: one line per constraint, visible feature or hidden, no lore, drawing is primary; cap = {{NOTE_LIMIT}} words; include CONFLICT / RECONCILE lines when needed.
8. Output shape.
9. Self-check (8 items).
For L1-L5, add the view-specific instruction and the source-reuse instruction.

STEP 5 — VALIDATE
Check:
- every requirement has exactly one ID and one line;
- no invented constraints;
- difficulty and annotation cap match;
- tension quota met (D1 0; D2 0-1; D3 1-2);
- cross-class priority stated;
- same-class conflicts classified (direct / incompatible / tension);
- direct conflicts have a tie_break;
- tension has a RECONCILE instruction;
- prompt is self-contained (defines P/F/Q/N and SVG rules);
- no "be creative" or style instructions.
Fix before output.

OUTPUT
A. Traceability table: requirement | ID | class | how to check.
B. Card JSON: id, difficulty, load, priority, constraints, bonus, conflicts, tension, tie_break, annotation_limit.
C. Complete prompt in one text code block.
D. Validation checklist with pass/fail.

Output only A-D.
```

## 10. 完整例子：7 条要求词 → D2 / 600 词

### 10.1 输入

```text
silicon-based
lives in molten rock
stores heat in a dorsal organ
exactly three feeding openings
no eyes
no more than four limbs
no vertebrae
```

### 10.2 对照表

| 要求词 | ID | 类 | 怎么查 |
|---|---|---|---|
| silicon-based | P1 | P | 晶体/矿物材质可见 |
| lives in molten rock | F1 | F | 黑曜石甲/热孔；背景可有岩浆 |
| stores heat in a dorsal organ | F2 | F | 背部热囊/热孔可见 |
| exactly three feeding openings | Q1 | Q | 数出 3 个，无多余口 |
| no eyes | Q2 | Q | 没有眼状结构 |
| no more than four limbs | Q3 | Q | 数出 ≤4 |
| no vertebrae | N1 | N | 剖面/骨骼里没有脊椎柱 |

**计数**：7 条 → D2（7–13）→ **600 词**；含 N，仍按 D2。

### 10.3 约束卡 JSON

```json
{
  "id": "X-002",
  "difficulty": "D2",
  "load": { "P": 1, "F": 2, "Q": 3, "N": 1 },
  "priority": "P>F>Q>N",
  "annotation_limit": 600,
  "constraints": {
    "P1": "silicon-based biochemistry",
    "F1": "lives in molten rock",
    "F2": "stores heat in a visible dorsal organ",
    "Q1": "exactly three feeding openings",
    "Q2": "no eyes",
    "Q3": "no more than four limbs",
    "N1": "no vertebrae"
  },
  "bonus": ["non-humanoid", "non-soft"],
  "conflicts": []
}
```

### 10.4 组装后的提示词（关键段）

```text
=== THE CONSTRAINTS ===

P1: silicon-based biochemistry.
F1: lives in molten rock.
F2: stores heat in a visible dorsal organ.
Q1: exactly three feeding openings.
Q2: no eyes.
Q3: no more than four limbs.
N1: no vertebrae.

=== THE DESIGN NOTE ===

- At most 600 words.
- One line per constraint:
  P1 → the visible feature that shows it
- If a constraint is hidden in this view, say so and where it is.
- If two constraints conflict, add a CONFLICT line.
- Do not write lore.
```

其余小节（角色、SVG 规则、优先级、加分项、输出形状、自检）直接沿用 L0 模板。

### 10.5 合格的注释结构

```text
P1 → translucent crystal limbs with mineral joints.
F1 → dark obsidian plates with glowing seams; the background is a cracked lava field.
F2 → a dorsal sac glows orange and has three heat vents.
Q1 → one central maw and two lateral siphons; exactly three feeding openings.
Q2 → no eyes; the head is a smooth armored dome.
Q3 → four limbs: two walking legs and two small manipulators.
N1 → no vertebrae; the body is supported by a mineral shell, visible in the cross-section.
```

注意：N1 这句在 L0 单视图里可能看不到，应该写 `hidden in this view; see the cross-section`；上面这句是给 L2 的写法。**L0 不要假装看得见。**

## 11. 校验清单（15 项）

- [ ] 每条要求词都有且只有一个 ID
- [ ] 没有新增约束、没有丢要求
- [ ] 复合句已拆、同义已并
- [ ] P/F/Q/N 分类正确
- [ ] 条数落在难度档内
- [ ] `annotation_limit` 与难度匹配（300/600/900）
- [ ] 跨类冲突有优先级
- [ ] 同级别冲突已分类（直接矛盾/不可兼得/Tension）
- [ ] 直接矛盾已二选一，或写了 `tie_break`
- [ ] Tension 有 `RECONCILE` 指令；D3 至少 1 个，D2 不超过 1 个
- [ ] 提示词自包含（定义了 P/F/Q/N、SVG 规则、输出格式）
- [ ] 注释规则写了上限，且说明"按任务不按视图"

- [ ] 没有"要有创意""画好看点"之类的话
- [ ] 把提示词给一个"空白模型"也能执行（自测一遍）

## 12. 常见错误

| 错误 | 症状 | 修法 |
|---|---|---|
| 把 N 当成 Q | "无脊椎"被写成"0 条脊椎" | 改成 N1，放到身体规划 |
| 把 Q 当成 F | "三个口"写成"有嘴" | 改成 Q1，精确数量 |
| 复合句不拆 | 一条里塞了栖息地 + 食性 | 拆成 F1/F2 |
| 模糊词不规范化 | "很怪""很大" | 改成可见/可数表述，或退回作者 |
| 同类冲突发货 | "无肢 + 恰好三肢" | 退回，删/改一条 |
| 同级别冲突一律当死题 | Tension 被误删 | 先分类；Tension 保留并写 `RECONCILE` |
| 直接矛盾没写 tie_break | 模型自己猜 | 补 `lower_id_wins` / `higher_id_wins` / `more_specific_wins` / `author_choice` |
| Tension 没写 RECONCILE | 注释只说"都满足了" | 加一行解释怎么共存 |
| D3 没有 Tension | 难度名不副实 | 至少加 1 个 T |
| 注释上限写死 300 | D2 也写 300 | 按难度 300/600/900 |
| 上限按视图算 | L1 六视图各 600 | 改成每任务 600 |
| 提示词依赖项目上下文 | 只写"按 P/F/Q/N"不解释 | 在提示词里解释四个组 |
| 加了"要有创意" | 结果不可比 | 删掉 |
| L1+ 没写 source reuse | 模型重画一只新生物 | 加"same creature as the source" |
| 注释写成世界观 | 300 词全是历史 | 改成逐条映射 |
| 注释超上限 | 600 词上限写了 800 | 压缩，或拆卡 |
