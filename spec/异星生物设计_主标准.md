# 异星生物设计标准（Xenobiology Design Standard）

> 工作名：**XenoDesign** / 传播名 **"Design an Alien"**
> 版本：v1.0 · 2026-11-13
> 定位：零安装、零服务器、无评分的开放标准。**只保留这一套题**；L5 的骑车是可选致敬关，不是另一套题。
> 一句话：给模型一组互相拉扯的生物学约束，看它能不能设计出一个**前后对得上、别人看得懂、守得住约束**的外星生物。

---

## 0. 你的约束，怎么落成设计

| 你的要求 | 设计决策 |
|---|---|
| 只保留异星生物设计 | 单一任务族；L5 骑车是可选致敬关，不是分支 |
| 直观观察，避免数据化 | 盲测推断 + 红黄绿检查 + 一致性矩阵，不做加权分 |
| 非常规对象，避开常规训练集 | 不用"龙/精灵/克苏鲁"等既有名词，用**约束组合**生成新题 |
| 测创造力、指令遵循、克制、逻辑 | 四类约束 + 设计说明书 + 跨视图一致性 |
| 剖面、骨骼、拓扑皮张、动态 | L0–L5 视图层级，从同一份源文件派生 |
| 可复现、可迭代 | Edition 冻结 + Manifest + 源文件哈希 + 新题版本 |
| 零运维、要 stars | 静态仓库 + GitHub Pages；视觉化设计包自带传播力 |

**它不是**：画技比赛、AGI 判定器、排行榜、需要注册/付费/上传 API Key 的 SaaS。

## 1. 它测什么

| 能力 | 怎么测 | 不测什么 |
|---|---|---|
| **指令遵循** | 每条约束都要在图上找到对应特征 | 画得美不美 |
| **克制** | 数量恰好、负约束不违反、说明书不超字数 | 想象力丰不丰富 |
| **逻辑** | 栖息地 → 解剖；剖面/骨骼与外观一致 | 生物学是否正确 |
| **创造力** | 自由需求 + 2 个自创特征；看跨模型差异 | 不打分 |
| **空间一致性** | 六视图、剖面、骨骼、拓扑皮张展开 | 工程制图精度 |
| **动态一致性** | 完整动画（跑跳）：肢体/开口/花纹不漂移 | 影视级动画 |
| **冲突处理** | 约束互相矛盾时，按优先级取舍并说明 | 谁更"聪明" |

**关键区分**：这套题不测"画技"，测的是**设计是否自洽、是否可被读懂、是否守约束**。一个画得丑但三个开口、剖面也对得上的生物，比一张漂亮但内部乱掉的图更强——因为它通过了可核对的检查。

## 2. 约束系统（核心）

### 2.1 四类约束

| 类 | 名称 | 定义 | 例子 | 怎么查 | 默认优先级 |
|---|---|---|---|---|---|
| **P** | 平行规定 | 全局参数，不规定器官位置（"不影响广延"） | 体型、硅基/碳基、环境温度、压力 | 材质/环境适应可见 + 说明书声明 + 比例线索 | **1（最高）** |
| **F** | 自由需求 | 开放式的设计委托：住在哪、靠什么活、有什么器官 | 生活在岩浆、储存热量、用振动交流 | 图上可见特征 + 说明书指认 | **2** |
| **Q** | 限定需求 | 精确数量或禁止项 | 恰好 3 个进食口、无眼、≤4 肢 | 可数、可检查"有没有多" | **3** |
| **N** | 自然规定 | 身体结构/分类规则，最具体 | 无脊椎、无足、外骨骼、无肺、辐射对称 | 剖面/骨骼里可见 | **4（最低）** |

**P 只放"不影响广延"的信息**：体型、生化、温度/压力。不要放"有几条腿""有没有脊椎""什么对称"——那些属于 Q 或 N。P 是画布，不是解剖。

**体型怎么查**：允许在画面角落画一个**无文字的 scale bar**，说明书里说明比例；没有 scale bar 就按说明书自报，评审不深究。其他 P（生化、温度、压力）看材质与环境适应特征。

### 2.2 优先级：P > F > Q > N

这不是"重要性排序"，而是**冲突时谁让路**：

- **P 是画布**：体型、生化、环境参数。它不能被违反，否则生物不再是这个生物。
- **F 是委托**：住在哪、怎么活。它定义设计目的；和具体数量冲突时，目的优先。
- **Q 是数量**：几个口、几条腿。它可数、可查；但和 F 冲突时，可以让路并说明。
- **N 是解剖细节**：有没有脊椎、有没有足。它最"严密"，因为它最具体；但具体不等于最高优先级——冲突时，细节让位于画布和委托。

**每张卡可以显式改写优先级**，例如 `N > Q > P > F` 做"硬解剖"专项。默认用 `P > F > Q > N`。

### 2.3 冲突协议

冲突不是 bug，是这套题最有价值的测试点。规则：

1. **先检测**：模型必须发现两条约束不能同时满足；
2. **再取舍**：按优先级保留高的，牺牲低的；
3. **后说明**：在说明书里写一行，格式固定：

```text
CONFLICT: F2 (rigid dorsal crest) vs N1 (no vertebrae) → followed F2; the crest is a mineral plate, not a vertebral column.
```

检查项 `X`（仅 D2/D3）：

- 有没有发现冲突？
- 有没有按优先级取舍？
- 说明和图是否一致？

模型若默默违反一条约束，记那条约束的红；若发现并说明，得 `conflict-aware` 徽章。**这比"全对"更能看出逻辑能力。**

### 2.4 加分项（独立于四类）

四类之外，另有**可选加分徽章**，不加数字分，只加标签：

| 徽章 | 要求 | 为什么 |
|---|---|---|
| `non-humanoid` | 没有人脸、人手、人形躯干、双足直立比例 | 避开"人形默认" |
| `non-soft` | 不是软体/黏液/果冻/纯触手团；有明确的骨架或甲壳 | 避开"软体默认" |
| `non-earth` | 没有可识别的地球动物轮廓（马、蜘蛛、鸟、狗） | 避开"地球模板" |
| `non-cliché` | 不是龙/昆虫人/发光水母这类常见奇幻原型 | 避开"题材默认" |

**为什么要有加分项**：如果只说"设计一个外星生物"，模型会收敛到触手人形、昆虫甲壳、发光水母这几类"最安全的平均答案"——已有研究称之为 **Median Trap**。约束组合负责把它推出去，加分项负责奖励"推得更远"。

加分项**不参与冲突优先级**，也不影响及格；它只是画廊里的一个标签。两个评审都认可才给。

### 2.5 难度：约束数量

难度（D）和视图层级（L）是**两条轴**，不要混：

| 难度 | 约束量 | 注释上限 | 冲突数 | 适合 |
|---|---|---|---|---|
| **D1 低** | 1P + 2F + 3Q + 0N = 6 | 300 词 | 0 | 第一次跑 |
| **D2 中** | 2P + 4F + 6Q + 1N = 13 | 600 词 | 0–1 | 常规评测 |
| **D3 高** | 3P + 6F + 9Q + 2N = 20 | 900 词 | 1–2 | 挑战/展示 |

- D2 是 D1 的三类约束翻倍，另加 1 条 N；
- D3 是 D1 的三倍，另加 2 条 N；
- 难度越高，越容易出现"必须取舍"的冲突；D3 的看点就是冲突处理。
- Q 就是上文的"限定需求"，也就是形态/数量限制。
- 注释上限按难度取 300/600/900，**按任务计，不按视图计**。
- 6/13/20 是标称构成；实际卡片按 4–6 / 7–13 / 14–20 落档，注释上限按档位取。

### 2.6 约束卡

```json
{
  "id": "X-001",
  "difficulty": "D2",
  "load": { "P": 2, "F": 4, "Q": 6, "N": 1 },
  "priority": "P>F>Q>N",
  "annotation_limit": 600,
  "constraints": {
    "P1": "body length 2–3 m",
    "P2": "silicon-based biochemistry",
    "F1": "lives in molten rock",
    "F2": "stores heat in a visible dorsal organ",
    "F3": "feeds on minerals",
    "F4": "communicates by vibration",
    "Q1": "exactly three feeding openings",
    "Q2": "no eyes",
    "Q3": "no more than four limbs",
    "Q4": "exactly two manipulators",
    "Q5": "no other mouth-like openings",
    "Q6": "no wings",
    "N1": "no vertebrae"
  },
  "bonus": ["non-humanoid", "non-soft", "non-earth"],
  "conflicts": []
}
```

`conflicts` 是出题人预埋的"可能冲突点"，D1 留空。冲突要设计成**可解释**的：比如 N1 说"无脊椎"，F 说"背部有分节支撑"——模型可以解释为"矿化板，不是脊椎"。不要出"无肢体 + 恰好三条腿"这种无法调和的死题。

## 3. 视图层级：L0–L5（L5 可选）

### 3.1 L0：单视图 + 按难度注释

- **产出**：`creature.svg` + `design.md`（≤ 难度上限：D1 300 / D2 600 / D3 900 词）。
- **视角**：侧视或 3/4 视，全身。
- **说明书**：每条约束一行，格式 `P1 → 图上可见的特征`。
- **遮掩声明**：如果某个特征在这一视角看不到，必须明说：

```text
Q1 → the third feeding opening is on the far side and is not visible in this view.
```

这不是扣分项，是**诚实性检查**：模型能不能区分"我画了"和"你看得见"。说得对，得 `honest-occlusion` 徽章；硬说看得见、图上却没有，记红。

**D3 的 900 词是硬上限**：写不下时优先保留 P/F，Q/N 用最短句。压缩本身就是克制测试。

### 3.2 L1：六视图

- **产出**：`front.svg`、`back.svg`、`left.svg`、`right.svg`、`top.svg`、`bottom.svg`。
- **要求**：同一生物，六个正交方向；肢体数、开口数、花纹、比例一致。
- **源文件**：L1 从 L0 的 `creature.svg` + `design.md` 复用，不重新设计。
- **检查**：跨视图一致性——每个特征在六个视图里都能对上；不允许"正面三条腿、背面四条腿"。

> 六视图对 2D SVG 来说很难，这是故意的。它测的是"模型有没有真正的三维账本"，而不只是"画得像"。

### 3.3 L2：剖面

- **产出**：`section.svg`（剖切/剖面）。
- **要求**：显示进食口如何连到消化道、内部腔体如何落在外轮廓内、材质是否与 P2 一致。
- **源文件**：复用 L0/L1，不重新设计。
- **检查**：三个口是否都连到腔体；腔体是否在身体内；有没有和岩浆环境冲突的器官（鳃、水肺）。

### 3.4 L3：骨骼 + 拓扑皮张

- **产出**：`skeleton.svg` + `pelt.svg`。
- **骨骼**：结构框架 + 淡淡的身体轮廓；关节/肢体与外形对齐。
- **皮张**：皮肤作为**一整张连续皮**取下、平铺，像老虎皮铺在地上；展示完整外表面、接缝/切口、花纹如何跨接缝连续；每个进食口/眼/肢体（或袖口）/尾根，在皮上必须是洞、边界或延伸；**不是剖面，也不是爆炸图**。
- **拓扑要求**：这是一张带洞的 2D 表面，不是多块皮拼贴；要能看出背/腹/左/右和接缝走向。
- **源文件**：复用 L0/L1。
- **检查**：骨架支撑轮廓；肢体数一致；皮张是**一张连续面**；孔洞全部对上；接缝/花纹连续；背/腹/左/右布局合理；没有画成剖面或爆炸图。

### 3.5 L4：完整动画

- **产出**：`motion.svg`（SMIL/CSS 动画，2–4 秒循环）；不能动画时交 8–12 帧 `frame01.svg` … 并注明。**4 帧故事板不算 L4。**
- **内容**：完整运动循环 `idle → run → jump → land → idle`。
- **检查**：循环无缝；帧间肢体/开口数量不变；运动顺序合理；接触/重量（脚不滑、跳跃有弧线）；T1–T5 特征持续；没有瞬移/换肢/穿模。
- **GIF**：不让模型直接输出 GIF。LLM 输出的是文本，GIF 是二进制光栅；主路径是动画 SVG（SMIL/CSS），降级是 8–12 帧 SVG。GIF 是维护者用 `rsvg-convert + ffmpeg` 导出的传播物料，不进入标准产物。

### 3.6 源文件复用

L1–L5 都必须基于同一份 **source package**：

```text
source/
├── creature.svg      # L0 主视图
├── design.md         # L0 说明书
└── preview.png       # 可选：给多模态模型看的渲染图
```

- 多模态模型：给 `preview.png` + `design.md`；
- 纯文本模型：给 `creature.svg` 源码 + `design.md`；
- 在 Manifest 里记录 `source_mode: "image" | "svg" | "text"`。

**"复用"复用的是设计，不是像素。** L2 的剖面必须和 L0 的开口数、材质、比例对得上；如果模型画出一个全新的生物，记 `source-drift` 红。

### 3.7 层级总表

| 层级 | 产出 | 主要检查 | 额外时间 | 适合 |
|---|---|---|---|---|
| **L0** | 单图 + 注释（按难度上限） | 约束可见、说明书准确、遮掩诚实 | ~10–15 分钟 | 所有人 |
| **L1** | 六视图 | 跨视图数量/比例/花纹一致 | +20 分钟 | 认真评测 |
| **L2** | 剖面 | 开口连通、腔体、材质 | +10 分钟 | 好奇的人 |
| **L3** | 骨骼 + 拓扑皮张 | 支撑、数量、单张连续、孔洞/接缝 | +20 分钟 | 硬核 |
| **L4** | 完整动画（跑跳） | 循环、数量、接触/重量 | +20 分钟 | 展示/研究 |
| **L5** | 致敬骑车（可选） | 车结构、骑乘接触、踩踏/平衡 | +20 分钟 | 彩蛋 |

L0 是标准，L1–L5 是可选深水区；L5 是致敬关，不计入核心链路。画廊按 `D? · L?` 标注，读者自己决定看多深。

## 4. Prompt 模板

### 4.1 L0（D2 示例）

```text
Design an original alien creature. Follow these constraints.

If constraints conflict, priority is: P > F > Q > N.

P1 (global): body length 2–3 meters.
P2 (global): silicon-based biochemistry.

F1 (free): lives in molten rock.
F2 (free): stores heat in a visible dorsal organ.
F3 (free): feeds on minerals.
F4 (free): communicates by vibration.

Q1 (exact): exactly three feeding openings.
Q2 (exact): no eyes.
Q3 (exact): no more than four limbs.
Q4 (exact): exactly two manipulators.
Q5 (exact): no other mouth-like openings.
Q6 (exact): no wings.

N1 (anatomy): no vertebrae.

Bonus (optional, independent): avoid humanoid features; avoid soft-bodied/blob features.

Draw the creature in one self-contained SVG with viewBox="0 0 512 512".
Show the full body in side or three-quarter view.
Do not use text labels, external images, or raster images.

Then write a design note of at most {{NOTE_LIMIT}} words (D1=300, D2=600, D3=900). Use one line per constraint:
P1 → the visible feature that shows it (or say it is hidden in this view).
...
If a constraint is hidden in this view, say so explicitly.
If two constraints conflict, add a line starting with "CONFLICT:" and state which one you followed.

Return the SVG first, then a line containing only "---", then the design note.
```

### 4.2 L1 追加

```text
Using the same creature as the source, draw six orthographic views:
front, back, left, right, top, bottom.
One SVG per view, named front.svg, back.svg, left.svg, right.svg, top.svg, bottom.svg.
Keep every count, pattern, and proportion identical across views.
Do not redesign the creature.
```

### 4.3 L2 追加

```text
Using the same creature as the source, draw a cutaway or cross-section SVG (same viewBox).
Show how all feeding openings connect to a shared digestive cavity.
Show how the internal cavity fits inside the body outline.
Do not label the image. Add one line per relevant constraint to the design note.
```

### 4.4 L3 追加

```text
Using the same creature as the source, also draw:
(a) skeleton.svg — the structural frame, with a faint body outline;
(b) pelt.svg — the skin removed as ONE continuous piece and unfolded flat,
like a tiger pelt stretched on the ground.

Keep the same viewBox. Show the complete outer surface, the seam lines, and how the pattern continues
across them. Every feeding opening, eye, limb socket (or sleeve), and tail base
must appear as a hole, a boundary, or an extension in the sheet.
Show the dorsal/ventral/left/right layout.

Do NOT draw a cutaway or an exploded view. Do NOT separate the skin into pieces.
Do not add blood, gore, or text labels.
```

### 4.5 L4 追加

```text
Using the same creature as the source, animate a full locomotion cycle:
idle -> run -> jump -> land -> idle.

Output motion.svg: one self-contained animated SVG using SMIL or CSS,
same 512x512 viewBox, 2-4 seconds, looping.

Keep the number of openings, limbs, and pattern identical in every frame.
Show contact and weight; no teleporting limbs, no sliding feet, no changing counts.

If you cannot animate, output 8-12 frames as frame01.svg ... frame12.svg and say so.
```

### 4.6 L5 追加（可选）

```text
Optional capstone. Using the same creature as the source, show it riding a bicycle.
Use the same viewBox.

Draw two wheels, a frame, handlebars, and pedals.
The creature must be on the bicycle, in contact with the seat and pedals,
not floating beside it. The bicycle is an object, not a second creature.

Animate a pedaling/balance cycle (ride.svg) or draw one clear scene (ride.svg).
Keep the creature's anatomy and pattern identical to the source.
```

### 4.7 输出顺序

始终 **图先、说明后**，中间用一行 `---` 分隔。这样评审可以先盲看，再读说明；模型也不能用文字逃避画图。

## 5. 检查方法（无评分）

### 5.1 盲测推断（核心）

只给一个人看 L0 的 `creature.svg`，不给 prompt、不给说明书，问：

1. 它生活在哪？
2. 它怎么吃东西？有几个进食口？
3. 它是什么材质/身体构成的？
4. 它有没有脊椎/足？身体结构像什么？
5. 它有什么特别的能力或器官？

记录原话，和约束、说明书对比：

- 能独立说出"岩浆""三个口""像石头/晶体" → 设计画明白了；
- 只说"一个很酷的石头怪物" → 部分通过；
- 说"一只恐龙/一只章鱼" → 失败，不管图多好看。

> 这不是新发明：OpenEnv 的 Pelican SVG 环境已经验证过，引导式提问会把卡通鸭判成鹈鹕，冷读图才靠谱。我们把它从"是不是鹈鹕"扩展成"能不能读出设定"。

### 5.2 一致性矩阵

逐条约束 × 视图，标 ✅/⚠️/❌/—：

| 约束 | L0 外观 | L1 六视图 | L2 剖面 | L3 骨骼 | L3 皮张 | L4 动画 |
|---|---|---|---|---|---|---|
| P2 硅基 | ✅ | ✅ | ✅ | ✅ | — | — |
| F1 岩浆 | ✅ | ✅ | ⚠️ | — | — | — |
| Q1 三口 | ✅ | ✅ | ❌ 只连了两条 | — | — | — |
| Q2 无眼 | ✅ | ✅ | — | — | — | — |
| N1 无脊椎 | ⚠️ | — | ✅ | ✅ | — | — |
| 克制 | ✅ | — | — | — | — | — |
| 冲突处理 | — | — | — | — | — | — |

**这不是分数，是索引。** 它让读者一眼看到"外观很好，剖面崩了"——这恰恰是最有价值的信息。

### 5.3 克制检查

逐项二元：

- 数量恰好（3 个开口，不多不少）；
- 负约束不违反（无眼、无翅膀、无其他口）；
- 肢体不超上限；
- 没有文字标签；
- 一个生物，不是拼贴；
- 说明书 ≤ 难度上限（300/600/900 词），每条约束一行；
- 没有大面积装饰遮住解剖结构。

### 5.4 冲突处理检查（X）

仅 D2/D3：

- 模型有没有发现预埋冲突？
- 有没有按 `P > F > Q > N` 取舍？
- `CONFLICT:` 行是否和图一致？
- 如果没有冲突，是否多写了假冲突？（多写也记黄）

### 5.5 分层检查表

**L0**

| 代号 | 检查 | 通过标准 |
|---|---|---|
| R | 能渲染 | 浏览器非空白 |
| P | 全局参数可见 | 材质/比例/说明书一致 |
| F | 自由需求可见 | 每条都能在图上指到 |
| Q | 数量/禁止项 | 可数、无多余 |
| N | 解剖规则 | 外观/说明书不矛盾 |
| T | 说明书准确 | 每条一行；遮掩声明正确 |
| K | 克制 | 无文字、无额外、≤ 上限 |

| 代号 | 检查 | 通过标准 |

## 6. 抗污染

### 6.1 约束生成器

七个维度随机组合：

| 维度 | 示例 |
|---|---|
| 栖息地 | 岩浆、深海热泉、冰下海洋、真空、沙暴、毒气云、地下洞穴 |
| 进食 | 3 个开口、过滤、寄生、光合、吃石头、吸热 |
| 生化 | 硅基、碳基、氨基础、硫基、等离子体、晶体 |
| 运动 | 6 肢、无肢、喷射、滚动、钻地、漂浮 |
| 防御 | 装甲、尖刺、拟态、酸液、放电 |
| 繁殖 | 孢子、出芽、卵、分裂、寄生 |
| 感官 | 无眼、回声、振动、热感应、磁场 |

10 × 8 × 6 × 8 × 8 × 6 × 6 ≈ **110 万种组合**；筛掉逻辑冲突后保留约 1 万条。每版抽 6 条，够用很多年。

### 6.2 不用专有名词

- 不写"龙""精灵""克苏鲁""异形"；
- 不要求画某个作品里的生物；
- 只用功能性约束（住哪、怎么吃、什么材质），让模型自己长形态。

这既避开版权，也避开"模型早就见过"的既有形象。

### 6.3 Edition

- **2 张锚点**：固定约束组合，跨版本重复，用来看趋势；
- **4 张新题**：每版新抽；
- **本地探针**：`probe.py` 随机抽约束，随时可测，不进入官方版。

一套 6 组，L0 全跑约 1 小时；跑 3 组也可以，标 `partial`。

### 6.4 诚实声明

公开约束卡一定会被训练。不承诺"无法污染"，只承诺：

- 每版换 4 组新约束；
- 组合空间大到无法全部背；
- 说明书 + 跨视图一致性，让"背一张图"不够用；
- 锚点与新题的差距，作为污染观察。

### 7.2 零依赖脚本

| 脚本 | 依赖 | 作用 |
|---|---|---|
| `probe.py` | Python 标准库 | 抽约束、打印 prompt、生成卡 JSON |
| `validate.py` | Python 标准库 | 检查文件齐全、数量、SVG 安全、哈希 |
| `build_gallery.py` | Python 标准库 | 生成静态 HTML，支持 `--local` 预览 |
| `render_source.py` | 可选 `rsvg-convert` | 把源 SVG 转 PNG，给多模态模型当输入 |

### 7.3 校验规则

- 含 `<!DOCTYPE` / `<!ENTITY` → 拒绝；
- `<script>`、`on*`、`<foreignObject>` → 拒绝；
- 外部 `href` / `xlink:href` → 拒绝；
- `<image>` 位图 → 拒绝；
- 单文件 > 512 KB → 拒绝；
- 根元素非 `<svg>` 或无 `viewBox` → 拒绝；
- 文件数量与 L 层级不符（如 L1 应有 6 个视图）→ 拒绝；
- 源文件哈希不匹配 → 拒绝；
- `<text>` → 标记 `text_label`，评审重点看。

**Manifest 最小字段**：

```json
{
  "standard": "xenodesign/v1",
  "edition": "2026.11",
  "card": "X-001",
  "difficulty": "D2",
  "level": "L0",
  "model": "provider/model",
  "model_version": "2026-10-01",
  "run_date": "2026-11-13",
  "source_mode": "n/a",
  "source_hash": null,
  "files": ["creature.svg", "design.md"],
  "checks": { "P1": true, "P2": true, "F1": true, "Q1": true, "N1": true },
  "badges": ["non-humanoid"],
  "notes": "Default settings; no tools."
}
```

L1 及以上：`source_mode` 填 `image | svg | text`，`source_hash` 填 L0 源文件的 sha256。示例只列了部分检查项；实际按卡片全部约束记录。

### 7.4 画廊安全

- 不内联用户 SVG，只用 `<img src="...svg">`；
- 仍然做消毒；
- 页面加 CSP `<meta>`；
- 不依赖前端 JS，每个模型/卡片/层级生成独立静态页；
- 社交预览图手工准备，不用 CI 渲染。

### 7.5 CI 与成本

- PR：`validate.py`，在评论里报错；
- main：`build_gallery.py` → Pages；
- 无 Secrets、无 API Key、无服务器；
- 公开仓库 Actions/Pages 免费；域名 ~$10/年。

## 8. 画廊与传播

### 8.1 首图就是产品

README 第一屏：

1. 一句话：**Can an AI design a coherent alien?**
2. 一张对比：同一张约束卡，6 个模型的 L0 外观；
3. 一张反差：某模型 L0 外观 vs L2 剖面——"外面像模像样，剖开只有两条消化道"；
4. 三步：copy prompt → paste → save SVG；
5. "Add your model" 和 `D2 · L0` 标签。

### 8.2 传播素材

- **盲测视频**："人类能猜出这只外星生物住哪吗？"
- **设计说明书**：像设定集，读者愿意读完；
- **"不可能解剖"栏目**：失败案例比成功案例更好笑；
- **徽章**：`non-humanoid`、`honest-occlusion`、`conflict-aware`，模型团队愿意贴；
- **Edition 节奏**：每 6–12 个月出新题，每次都是一次发布。

### 8.3 内容红线

**PG-13**。皮张图按"博物馆皮张展开图"画，不流血、不露内脏细节；不做寄生爆体、眼球寄生这类猎奇方向。默认不放在首屏。

## 10. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 约束歧义 | 评审吵架 | 试跑 3 个模型；两人盲审；歧义卡淘汰 |
| 创造力主观 | 无法比较 | 固定 P/F/Q/N 做横向；自创只展示，不打分 |
| 题太复杂，没人跑 | 冷启动失败 | L0 默认；D1 保底；先做 3 组快跑 |
| 模型用文字逃避 | 结果失真 | 禁文字；图先于说明；校验器拦截 `<text>` |
| 输出都是"平均怪物" | 无聊 | 怪约束 + 负约束 + 加分徽章 + 每版换题 |
| 评审负担大 | 维护崩溃 | 提交者自填；社区抽查；只对 featured 全查 |
| 模型普遍画不好 | 画廊难看 | 失败也是内容；L0 保底；把"崩坏"做成栏目 |
| 皮张/解剖引人不适 | 举报 | PG-13；博物馆皮张图；默认折叠 |
| 版权 | 法律风险 | 不用专有生物；约束原创；提交者授权 |
| GIF 不可行 | 期待落空 | 动画 SVG / 8–12 帧；GIF 只做导出 |
| 污染 | 老题失效 | Edition + 探针 + 组合空间；诚实说明 |

## 13. 参考与先例

- [提示词撰写指南.md](提示词撰写指南.md) — 从要求词生成完整提示词、注释上限规则。
- [提示词素材库.md](提示词素材库.md) — P/F/Q/N/加分项的现成菜单（7 P / 26 F / 24 Q / 10 N / 6 B）。
- [XSCT：异星生物图鉴编撰](https://www.xsctbench.com/testcase/l_creative_027/qwen3.5-omni-flash) — 纯文本异星生物设定题，说明需求存在；但不画图、不查跨视图一致性。
- [Ontology of the Alien: Escaping the Median Trap](https://github.com/emergent-wisdom/ontology-of-the-alien) — 解释"只说'要有创意'会收敛到少数原型"；本文的约束组合与加分项就是回应。
- [CrIB: Benchmark for Combinational Creativity](https://www.emergentmind.com/topics/creative-invention-benchmark-crib) — 组合创造力基准，含绘画/异星语言；它用归一化分数，我们用无分数 + 视觉检查。
- [InternSVG / SArena](https://export.arxiv.org/pdf/2510.11341) — 学术界的统一 SVG 任务基准，含动画与科学图表；重型管线，我们是零安装轻量版。
- [VAnim](https://icml.cc/virtual/2026/poster/64100) — LLM 驱动的矢量动画生成；说明动画 SVG 可行但很难，所以本文把完整动画作为主路径，8–12 帧作为降级。
- [Pelican SVG Environment](https://huggingface.co/spaces/sergiopaniego/pelican-svg-env) — 盲测描述 + 二元检查的先行验证。

---

> **一句话**：这套题的核心不是"让 AI 画一只很酷的外星生物"，而是"给它一组互相拉扯的设定，看它能不能把设定画成一个前后对得上、别人看得懂、守得住约束的设计"。漂亮是加分，自洽才是及格线。
